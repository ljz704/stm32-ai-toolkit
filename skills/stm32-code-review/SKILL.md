# STM32 固件代码审查

## 审查维度

### 1. 命名规范检查（对照全局 CLAUDE.md）
- [ ] 函数名：`ModuleName_ActionName()` 格式
- [ ] 全局变量：`g_` 前缀
- [ ] 宏定义：全大写 + 模块前缀
- [ ] 局部变量：驼峰命名
- [ ] 结构体/枚举：符合项目规范

### 2. 内存安全审查
- [ ] 无 `malloc/free` 使用
- [ ] 无递归调用
- [ ] 数组访问有边界检查
- [ ] 指针使用前已判空
- [ ] 字符串操作使用安全版本（如 `strncpy` 而非 `strcpy`）

### 3. 中断安全审查
- [ ] 中断服务函数内无阻塞操作（delay、printf 等）
- [ ] 中断服务函数内无浮点运算（FPU 上下文保存问题）
- [ ] 共享变量有 `volatile` 修饰
- [ ] 临界区保护使用正确（`__disable_irq()` / `__enable_irq()`）

### 4. 外设配置审查
- [ ] 初始化顺序符合全局规范：RCC 时钟使能 → GPIO 配置 → NVIC 中断 → 外设参数配置（含 DMA）→ 使能外设
- [ ] 中断优先级配置合理（数字越小优先级越高，注意抢占/子优先级）

### 5. 硬件相关审查
- [ ] 寄存器配置有参考手册章节注释
- [ ] 延时函数是否考虑主频变化
- [ ] ADC 采样时间是否满足要求
- [ ] PWM 死区时间是否配置（HRTIM/高级定时器）

### 6. 可维护性审查
- [ ] 魔法数字已用 `#define` 替代
- [ ] 函数长度 < 50 行（建议）
- [ ] 注释清晰，复杂算法有说明
- [ ] 无冗余代码、无死代码
- [ ] 每个函数有 Doxygen 注释（@brief/@param/@retval，全局规范强制）
- [ ] 寄存器配置注释注明参考手册章节（如 `// REF: RM0364 Section 18.4.1`）

## 审查输出格式

对每个审查维度，输出：
```markdown
## 维度X：命名规范
- ✅ `ADC_Init()` — 符合规范
- ❌ `read_rn8209()` — 应为 `RN8209_ReadReg()`
- ⚠️ `temp` — 局部变量建议用 `temperatureValue` 或 `tempVal`

## 维度X：内存安全
- ❌ Line 45: `char buf[10]; strcpy(buf, input);` — 缓冲区溢出风险
  建议: `strncpy(buf, input, sizeof(buf)-1); buf[sizeof(buf)-1] = '\0';`
```

最后给出：
- **严重问题**（必须修复）：内存泄漏、中断不安全、硬件损坏风险
- **建议优化**（推荐修复）：命名不规范、可维护性差
- **评分**：X/100
