# STM32 调试问题分析 v2.0

## 触发条件
用户描述以下场景时触发：
- "程序跑飞了"、"死机"、"卡死"
- "HardFault"、"进入中断出不来"
- "串口没输出"、"LED 不亮"
- "ADC 采样不准"、"PWM 没波形"
- "烧录后没反应"、"复位后没运行"
- 用户粘贴了串口日志、报错信息、寄存器值

## 核心原则
1. **先收集结构化信息，再分析**
2. **展示原始数据后再给结论**
3. **读取 `.claude/memory/known_issues.md`，检查是否有历史教训**

## 分析流程

### Step 1：读取项目记忆
1. 读取项目 `CLAUDE.md` 确认 MCU 型号和配置
2. 读取 `.claude/memory/known_issues.md` 检查历史教训
3. 读取 `.claude/memory/pin_usage.md` 检查引脚冲突

### Step 2：分类定位

#### 类型 A：上电即死机/无反应
排查顺序：
1. 时钟未起振 → 示波器抓 HSE
2. 启动文件不匹配
3. SystemInit 卡死 → PLL 配置
4. 全局变量初始化溢出
5. 中断未配置但触发了

#### 类型 B：HardFault
分析必备信息：
- LR（判断线程/Handler 模式）
- PC（出错指令地址）
- CFSR（精确错误原因）
- BFAR（总线错误地址）

常见原因对照表：
| CFSR 标志 | 含义 | 常见原因 |
|-----------|------|----------|
| IBUSERR | 指令总线错误 | 跳转到无效地址 |
| PRECISERR | 精确数据总线错误 | 访问未映射地址、数组越界 |
| IMPRECISERR | 非精确数据总线错误 | DMA 访问无效地址 |
| STKERR | 压栈错误 | 栈溢出 |
| UNSTKERR | 出栈错误 | 栈被破坏 |
| NOCP | 协处理器错误 | 使用 FPU 但未开启 |
| INVPC | 无效 PC 加载 | 中断返回时 LR 错误 |

#### 类型 C：外设不工作
排查顺序：RCC → GPIO → NVIC → 外设使能 → DMA → 示波器验证

#### 类型 D：通信异常
排查顺序：波特率 → 引脚配置 → 上拉电阻 → 共地 → 协议时序

### Step 3：串口数据收集（如需要）
1. 调用 `serial_list_ports` 找可用串口
2. 调用 `serial_read` 或 `serial_monitor_start` 读取数据
3. **必须展示原始数据**后再分析

### Step 4：给出修复方案
- 针对定位到的问题，给出具体代码修改
- 如果信息不足，给出「下一步诊断步骤」
- **修复后必须建议用户调用 `keil_build` 验证编译**
